# 架构决定

## 共同记录与原生运行时

平台拥有会话、项目、成员配置、公开消息、候选结果、判断与审计事件。SQLite 保存这些记录；同一会话的所有参与者读取相同版本的共享内容。

每个成员保留独立原生会话标识。Codex 使用 app-server，Cursor 使用 headless CLI，Reasonix 使用 ACP。平台负责分发信息、推进讨论和判断何时停止，Agent 负责自己的上下文压缩、工具调用和运行环境。

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 平台保存共同记录，复用 Agent 运行时 | 保留原有能力、认证和会话机制；故障更容易定位 | 必须记录各 Agent 使用的版本；内部压缩策略不同 |
| 平台重做全部记忆与工具循环 | 可严格控制上下文分发及工具实现 | 会变成另一个 Agent 运行时，维护、模型适配和验证成本明显上升 |

一期采用前者。公开正文完整保存，首次接入发送完整共同记录，后续按各原生会话的同步游标发送新增记录，明确标识来源与版本。仅在原生运行时返回完整回复后推进游标；失败或接收不确定时暂停，并在下一次重新建立会话、完整同步。过大的输入明确暂停，不静默截断。原生会话不是共同事实的权威来源。后续若有上下文漂移证据，再替换相应 seam，不重做所有 Agent。

## 接入 interface

适配层暴露能力发现、创建或恢复 local_session、执行一轮、公开进度事件、取消与释放连接。能力包括模型、可调参数、项目访问和公开推理摘要。调用方不需要了解 stdio、CLI 或 A2A wire format。

新增原生实现按同一 interface 注册；第三方 Agent 通过标准 Agent Card 发现。A2A 传输使用官方 SDK，不用自定义“类似 A2A”的消息格式冒充协议兼容。

## 收敛

每轮先收集独立观点，再对一份编号明确的候选结果进行交流和判断。判断必须明确给出接受、修改或拒绝，以及对具体参与者的分歧。判断关联候选版本。

全部参与者接受同一候选版本才是共识。分歧终局需两个参与者在看到对方意见后，明确声明相互冲突且不可让步的立场。无响应、空结果、错误和单纯轮数上限都不是分歧终局。

## 可见性

详情展示公开回答、原生会话标识、工具活动与供应方提供的公开推理摘要。未公开的内部思维不复制或伪造。原始密钥、环境变量和原生敏感诊断不暴露给网页。

## 一期边界

本机单用户运行，绑定回环地址，校验请求来源与数据。既有只读执行策略仍保留；不增加自定义权限或职责产品功能。
