### v0.3：Agent 运行核心

- 用户要求以 Agent 设计为主。已落地任务目标与固定约束、用户原文保留、稳定角色、模型容量/输出/额外预留、计数与 usage 校准、结构化 checkpoint 引文、当前轮次压缩、公共证据回取、实际请求审计、一次超限恢复和更严格的分歧判断。
- 初始候选来源随用户轮次轮换；只有当前候选前后两轮同一对成员均明确保留双向不可让步立场才报告僵局。错误、输出耗尽、超限恢复前的旧阶段回复都不会混入终局。
- API 平台规则走协议的 system/instructions 层，计数也包含该规则；传输元数据不含认证头。未观察到 usage 的估算与 usage 校准估算分别标识，未知窗口不猜测；用户较大的窗口配置不能绕过已知供应方限制。
- 模型摘要按容量分批，每批最多修复一次格式/引文，整次成功且减小投影才保存 checkpoint；每次摘要调用独立审计。原生摘要请求逐批重新建立运行时会话。
- 固定指令过大时不静默丢弃。文件快照增加项目、路径、哈希和捕获时间，项目切换后不自动注入旧材料。平台身份在加入时建立，重启迁移旧原生标识，项目切换保持平台身份。
- 真实 Codex 与直接 DeepSeek 带固定约束讨论并达成当前请求的共识；两者均通过平台 readMessageIds 回取指定公共原文后继续判断。
- 使用真实历史的隔离副本验证较长压缩：原始 19 条记录全部保留，v2 checkpoint 经过 5 批覆盖 14 条，所有结构化引文都精确匹配原文。未修改原始会话的历史内容。
- 真实验证观察到输出截断、摘要未减小输入、缺少本批引文：均拒绝保存 checkpoint。已为引文覆盖提供明确提示与一次修复反馈。
- 压缩后继续讨论暴露实际范围漂移：候选回到历史整套方案、判断误用旧目标。已新增 latestRequestId，明确本轮请求优先，并把 acceptsSolution 定义为充分回答本轮请求；终局与请求关联 requestSourceId 和任务版本。后续真实 DeepSeek 已围绕当前论证问题给出并接受答复。该观察不宣称彻底证明语义防漂移。
